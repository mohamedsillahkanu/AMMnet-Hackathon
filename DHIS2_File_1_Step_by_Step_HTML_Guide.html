DHIS2 Data Entry Form

Step-by-Step Guide: Creating a Complete Aggregate Data Entry Form

Purpose of this guide

This guide walks through the complete process of creating an aggregate data-entry form in DHIS2. Follow each step in order. After completing each step, insert a screenshot of your DHIS2 screen in the designated screenshot area.

Step 1: Open DHIS2

Open your DHIS2 instance in a web browser and log in with an account that has the required metadata configuration permissions.

Action: Open your DHIS2 URL → Enter username → Enter password → Log in

What to check

  • Confirm that you are logged into the correct DHIS2 instance.
  • Confirm that you have access to the Maintenance/Metadata Management functions.
Expected result: You should see the DHIS2 home page/dashboard.
📸 INSERT SCREENSHOT HERE Screenshot showing the DHIS2 login/home page.
Step 2: Open Data Elements

Open the Maintenance or Metadata Management area and navigate to Data Elements.

Click: Maintenance / Metadata Management → Data Elements

What to do

Review the existing data elements first. If the required data element does not already exist, create a new one.

Expected result: The Data Elements list should be displayed.
📸 INSERT SCREENSHOT HERE Screenshot showing where Data Elements is located and the Data Elements list.
Step 3: Create a New Data Element

Click the button for creating a new data element.

Click: + New

Complete the data element information

Example:

Name: Malaria Suspected Cases
Short Name: Malaria Suspected
Value Type: Integer
Aggregation Type: Sum
Domain: Aggregate

Add a clear description explaining exactly what should be reported.

Expected result: The new data element is saved and appears in the Data Elements list.
📸 INSERT SCREENSHOT HERE Screenshot of the Create Data Element screen, showing the fields that must be completed.
Step 4: Create All Required Data Elements

Repeat Step 3 for every indicator that will appear in the reporting form.

Example malaria data elements:

• Malaria Suspected Cases
• RDT Tested
• Microscopy Tested
• RDT Positive
• Microscopy Positive
• ACT Treatment
• Severe Malaria Treatment
• Pre-Referral Treatment
• Malaria Deaths
• Malaria Referrals

Important

Use one data element for one measurable concept. Avoid creating unnecessary duplicate data elements.

📸 INSERT SCREENSHOT HERE Screenshot showing the completed Data Elements list.
Step 5: Create Category Options

If your form needs disaggregation such as sex or age group, create the required category options.

Click: Categories / Category Options
Example:

Category: Sex
Options: Male, Female
Expected result: The category options are available for use in a category.
📸 INSERT SCREENSHOT HERE Screenshot showing the category/category option creation screen.
Step 6: Create Categories

Group the relevant category options into a category.

Click: Categories → + New
Example:

Category name: Sex
Category options: Male, Female
Expected result: The category is saved and can be used when creating a category combination.
📸 INSERT SCREENSHOT HERE Screenshot of the category creation screen.
Step 7: Create a Category Combination

Create a category combination when data needs to be disaggregated by one or more categories.

Click: Category Combinations → + New
Example:

Name: Sex
Category: Sex
Expected result: The category combination is available for assignment to data elements or datasets.
📸 INSERT SCREENSHOT HERE Screenshot showing the Category Combination creation screen.
Step 8: Create the Data Set

Create the dataset that will contain all the data elements for the reporting form.

Click: Data Sets → + New
Example:

Name: Monthly Malaria Service Reporting
Short Name: Malaria Monthly
Period Type: Monthly
Description: Monthly reporting of malaria services and outcomes
Expected result: The dataset is created and available for configuration.
📸 INSERT SCREENSHOT HERE Screenshot of the Create Data Set screen.
Step 9: Add Data Elements to the Data Set

Add all the data elements that belong to the reporting dataset.

Open the Data Set → Configure/Edit data elements → Add the required data elements

Recommended order

  1. Malaria Testing
  2. Malaria Results
  3. Treatment
  4. Outcomes
Expected result: All required data elements are associated with the dataset.
📸 INSERT SCREENSHOT HERE Screenshot showing the data elements being added to the dataset.
Step 10: Assign the Data Set to Organisation Units

Assign the dataset to the organisation units that are expected to submit reports.

Open Data Set → Organisation Units → Select the reporting organisation units
Example:

Sierra Leone → Bo District → Selected Health Facilities
Expected result: The dataset becomes available for data entry at the assigned organisation units.
📸 INSERT SCREENSHOT HERE Screenshot showing the organisation-unit assignment screen.
Step 11: Create Sections

Organise the dataset into logical sections so that the final data-entry form is easy to use.

Data Set → Options → Manage Sections
Suggested sections:

1. Reporting Information
2. Malaria Testing
3. Malaria Results
4. Treatment
5. Outcomes
Expected result: The dataset is divided into clear reporting sections.
📸 INSERT SCREENSHOT HERE Screenshot showing the Manage Sections screen.
Step 12: Add Data Elements to Each Section

Select the appropriate data elements for each section and arrange them in the order in which users should report the information.

Example — Malaria Testing:

Suspected malaria cases
RDT tested
Microscopy tested
Expected result: Each section contains only the fields relevant to that part of the report.
📸 INSERT SCREENSHOT HERE Screenshot showing data elements being assigned to a section.
Step 13: Make Required Fields Compulsory

Identify the fields that must be completed before a report can be considered complete.

Data Set → Edit Compulsory Data Elements

Important

Do not make every field compulsory. Only mark fields as compulsory when the programme reporting requirements require them.

Expected result: Users are required to complete the selected fields during data entry.
📸 INSERT SCREENSHOT HERE Screenshot showing the compulsory data-element configuration.
Step 14: Create Validation Rules

Create rules that identify logically impossible or inconsistent combinations of reported values.

Examples:

RDT Positive ≤ RDT Tested
Microscopy Positive ≤ Microscopy Tested
Malaria Deaths ≥ 0
Open: Validation Rules → + New
Expected result: DHIS2 can identify reporting inconsistencies when the form is validated.
📸 INSERT SCREENSHOT HERE Screenshot showing the validation-rule creation screen.
Step 15: Configure Data Set Sharing

Configure metadata sharing so that the appropriate users and user groups can access the dataset.

Data Set → Sharing / Access

Check

  • Who can view the dataset?
  • Who can enter data?
  • Who can complete the dataset?
  • Which organisation units are available to the users?
Expected result: The intended users can access the dataset according to their permissions.
📸 INSERT SCREENSHOT HERE Screenshot showing the sharing/access configuration.
Step 16: Open Data Entry

Open the Data Entry application and select the organisation unit, dataset and reporting period.

Data Entry → Organisation Unit → Data Set → Reporting Period
Expected result: The newly created data-entry form opens.
📸 INSERT SCREENSHOT HERE Screenshot showing the Data Entry screen with the new dataset.
Step 17: Enter Test Data

Enter realistic test values into the form.

Example:

Suspected cases: 250
RDT tested: 220
RDT positive: 150
ACT treatment: 180
Malaria deaths: 0

Confirm that the fields accept the expected values and that the calculated/validation behavior works correctly.

📸 INSERT SCREENSHOT HERE Screenshot showing the completed test report.
Step 18: Test Validation

Enter an intentionally invalid value to confirm that the validation rule is working.

Example:

RDT Tested = 100
RDT Positive = 150

Run validation and confirm that DHIS2 identifies the inconsistency.

Expected result: DHIS2 displays the relevant validation error.
📸 INSERT SCREENSHOT HERE Screenshot showing the validation error message.
Step 19: Correct the Error and Complete the Report

Correct the invalid value, run validation again, and complete the reporting form according to your DHIS2 workflow.

Correct value → Run Validation → Save → Complete
Expected result: The report passes validation and can be completed.
📸 INSERT SCREENSHOT HERE Screenshot showing successful validation and/or completed status.
Step 20: Final Review

Review the complete form before deploying it to users.

  • Check every data element.
  • Check every section.
  • Check compulsory fields.
  • Check validation rules.
  • Check organisation-unit assignment.
  • Check user access.
  • Test the reporting period.
  • Test with realistic and invalid data.
  • Test on the devices that users will actually use.
Expected result: The complete DHIS2 data-entry form is ready for user acceptance testing.
