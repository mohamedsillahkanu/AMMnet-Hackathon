DHIS2 Data Entry Form — Visual Design Guide

Step-by-step guide for designing a professional, colour-coded custom web data-entry form.

How to use this guide: Complete Topics 1 to 3 first. Then use this guide to design the appearance. After every step, insert a screenshot from your own DHIS2 system in the marked area.
Step 1: Open the Data Set

Open the dataset that you created in the first guide.

Click: Maintenance / Metadata Management → Data Sets → Select your dataset
Expected result: You can see the dataset configuration and its options.
📸 INSERT SCREENSHOT HEREShow the DHIS2 Data Set page and the dataset options menu.
Step 2: Open the Data Entry Form Designer

Open the option used to design the custom data-entry form.

Click: Data Set → Options → Design Data Entry Form

This opens the DHIS2 form editor. The exact menu names can vary slightly by DHIS2 version.

Expected result: The custom form/WYSIWYG editor opens.
📸 INSERT SCREENSHOT HEREShow the Design Data Entry Form option and the form designer.
Step 3: Understand the Form Designer

Before adding colours, identify the main parts of the editor:

  • Editing area
  • Formatting toolbar
  • Source/HTML mode
  • DHIS2 data-element insertion controls
  • Save/update controls
Action: Open Source/HTML mode if your DHIS2 version provides it.

Step 5: Create the Main Form Header

The first part of the form should clearly identify the reporting programme and form.

┌─────────────────────────────────────────────────────┐
│  NMCP MALARIA MONTHLY REPORT                        │
│  Routine Malaria Service Reporting                  │
└─────────────────────────────────────────────────────┘

Use the primary colour #1565C0 for the header background and white text.

Design: Add the programme/form title at the top. Keep the title short and prominent.
📸 INSERT SCREENSHOT HEREShow the form header being created or the resulting header.
Step 6: Design the Reporting Information Section

Create a clear first section containing the information needed to identify the report.

REPORTING INFORMATION
────────────────────────────────────────
Organisation Unit:   [ Bo Government Hospital ▼ ]
Reporting Period:    [ September 2026 ▼ ]
Design: Use a blue section heading and a light-blue instruction panel underneath it.
Design principle: Users should immediately know which facility and reporting period they are entering.

Step 11: Add Instruction Panels

Use light-blue information boxes for short instructions.

ℹ INFORMATION
Enter the number of patients tested for malaria
during the reporting month. Do not include tests
performed outside the reporting facility.
Design: Background #E3F2FD; left border #1565C0; short text only.
📸 INSERT SCREENSHOT HEREShow an instruction panel in the form.
Step 12: Add Warning and Error Styling

Do not use red for normal fields. Reserve it for errors.

⚠ WARNING
RDT positive cases cannot exceed the number of
RDT tests performed.

Use pale orange for warnings and pale red for actual validation errors.

Design: Warning #FFF3E0; Error #FFEBEE.

Step 13: Add a Summary Area

A summary block can make the form easier to review before completion.

REPORT SUMMARY
────────────────────────────────────────
Suspected cases             250
Total tested                220
Total confirmed             170
ACT treatment               180
Malaria deaths                0
Design: Use a light-grey or light-blue background. Make calculated/summary values visually distinct from input fields.
📸 INSERT SCREENSHOT HEREShow the summary area.
Step 14: Design the Bottom Action Area

Keep the final actions together.

────────────────────────────────────────────────
[ Run Validation ]             [ Save ] [ Complete ]
Design: Keep the action area simple. Do not use multiple competing button colours.
📸 INSERT SCREENSHOT HEREShow the bottom action area.
Step 15: Insert the DHIS2 Data Elements

Now place the actual DHIS2-linked data elements into the designed sections.

Important: Insert the fields using the DHIS2 form designer's data-element insertion mechanism. Do not replace them with ordinary HTML input elements.
  • Insert Suspected Cases under Malaria Testing.
  • Insert RDT Tested and Microscopy Tested underneath it.
  • Insert RDT Positive and Microscopy Positive under Results.
  • Insert ACT and severe malaria fields under Treatment.
  • Insert deaths and referrals under Outcomes.

Step 17: Test Desktop Display
  • Check the form at normal browser zoom.
  • Check that labels are readable.
  • Check that fields do not overlap.
  • Check that section headers are consistent.
  • Check that long labels wrap correctly.
📸 INSERT SCREENSHOT HEREInsert a full-screen desktop screenshot of the final form.
Step 18: Test Validation and User Experience

Enter both valid and invalid values and verify that the visual design does not hide validation messages.

Example: RDT Tested = 100; RDT Positive = 150 → validation should identify the inconsistency.
📸 INSERT SCREENSHOT HEREInsert the screenshot showing the validation message.
Step 19: Test the Form With Users

Ask a small number of intended data-entry users to complete the form without explaining every field to them.

  • Can they find the reporting period?
  • Do they understand what each section means?
  • Can they identify which fields require entry?
  • Can they understand validation messages?
  • Can they complete the report without unnecessary scrolling?
📸 INSERT SCREENSHOT HEREInsert a screenshot of the form during user testing.
Step 20: Final Approval Version

Once the form has been tested and approved, capture the final version for your implementation documentation.

Final deliverable: A professional, structured DHIS2 web data-entry form with consistent colours, clear sections, instructions, validation feedback and an easy reporting flow.
